# Скрипты: Python 3.9+, стандартная библиотека

Запускай из рабочего проекта, подставляя путь к папке скилла. `--output` пишет только внутри корня вывода: рабочего каталога, а в Ouroboros — `OUROBOROS_SKILL_STATE_DIR`. Относительный путь считается от этого корня; путь снаружи (абсолютный или через `..`) отклоняется с кодом 2. Каталог вывода внутри корня создай заранее. Скрипты сохраняют существующие файлы: для нового запуска используй новое имя. Если опустить `--output`, результат доступен в stdout: JSON у сборщика и калькулятора, HTML у генератора отчёта.

## Сбор

```bash
python3 /path/to/ai-b2b-radar/scripts/collect.py --output signals.json
python3 /path/to/ai-b2b-radar/scripts/collect.py --source github --query 'invoice automation in:readme pushed:>=2026-09-15' --limit 50 --output invoices.json
python3 /path/to/ai-b2b-radar/scripts/collect.py --source habr-ml --source ainews --since 2026-09-15 --output feeds.json
python3 /path/to/ai-b2b-radar/scripts/collect.py --url https://example.com/product --output page.json
python3 /path/to/ai-b2b-radar/scripts/collect.py --html saved.html --url https://example.com/product --output parsed.json
```

Без `--source` проверяются GitHub Search + Trending, две ленты Хабра, AINews, Hugging Face Models + Spaces, Show HN, YC Launches. Доступные имена показывает `--help`. Дата по умолчанию — начало дня семь дней назад по UTC; `--limit` от 1 до 100 на поток, по умолчанию 30. Время в `--since` без часового пояса трактуется как UTC. Повторяемый `--query` задаёт собственные запросы GitHub вместо стандартных тематик; его можно передать при сборе всех источников или с `--source github`.

Для каждого канала JSON содержит `status`, ошибки, `latest_seen`, `scanned`, `unique`, `older`, `future`, `has_more` и `items`. При полной недоступности канала доступны его статус, ошибка и пустой `items`. Нормализованные записи содержат `title`, `url`, `kind`, `published_at`, `modified_at`, `period_status`, `excerpt`; у HN также `discussion_url`.

`status=ok` означает успешную обработку ограниченной выборки. `stale` — максимальная доступная дата раньше периода; `partial` — извлечена лишь часть данных или требуется браузер; `unavailable` — запрос/разбор завершился ошибкой. Статусы `period_status` отражают дату публикации либо последнего изменения, а дату реального события агент проверяет отдельно.

Сборщик сохраняет записи периода и записи без дат; число старых и будущих записей выводится отдельно. `has_more` относится к полученному ответу, а не ко всему каталогу. Сайты и API дают ограниченные окна выдачи. GitHub Search делит бюджет между темами ai-agents, workflow-automation, document-processing и machine-learning; агент дополняет их поиском по бизнес-задачам. Show HN даёт выборку запусков; Launch HN и дополнительные страницы просматриваются по необходимости.

При `--url` результат — заголовок, до 40 тысяч символов текста и до 300 ссылок; поле `truncated` указывает обрезку текста. Сборщик читает статический HTML. Для контента, который появляется после выполнения JavaScript, используй доступный браузер. Сохраняются ссылки, но по ним автоматически не выполняется дальнейший обход.

Сетевые запросы ограничены таймаутом 15 секунд и ответом 8 МБ; проверяются публичные адреса, в том числе при редиректах. Сбор выполняется последовательно с одной попыткой на запрос. Общий бюджет времени `--budget` (по умолчанию 240 секунд, 10–3600) держит сбор внутри лимита исполнения: после него новые запросы не выполняются, собранное сохраняется, а недоделанные каналы получают `partial`/`unavailable` с ошибкой `collection time budget exhausted`. Ошибки одного канала сохраняются рядом с результатами остальных; битая запись ленты пропускается и попадает в `errors` канала, не обрывая его. Exit code: 0 — результат получен (включая частичное покрытие), 1 — все запрошенные каналы недоступны, 2 — ошибка ввода/вывода. Всегда читай статусы в JSON.

## Оценки и расчёт

Основной вход для готового дайджеста — [типизированный JSON](report.md). `report.py` вызывает калькулятор сам. Для отдельного расчёта `score.py` также принимает JSON-массив карточек, содержащих `id`, `technology`, `product`, `buyer`, `confidence` (`low`, `medium`, `high`), `confidence_reason` и `criteria` с ровно пятью ключами:

| Ключ | Критерий |
|---|---|
| `pain` | Боль |
| `buyer` | Покупатель |
| `value` | Экономическая ценность |
| `repeatability` | Повторяемость |
| `timing` | Отличие / момент |

Каждое значение критерия имеет форму:

```json
{
  "value": 15,
  "reason": "Конкретное обоснование из исследованных материалов",
  "kind": "hypothesis",
  "evidence": ["https://example.com/customer-story"]
}
```

Это иллюстрация формата. Для реального отчёта подставляй проверенные ссылки. `value`: 0, 5, 10, 15, 20 или `null`. `kind`: `fact`, `vendor_claim`, `hypothesis`, `unknown`. Для `null` используй `unknown` и объясни недостающие данные. Для факта/заявления поставщика требуется хотя бы одна ссылка или ссылка на предоставленный файл; для гипотезы и неизвестного допустим пустой массив. Вся запись гипотезы, включая дополнительные поля агента, сохраняется в результате.

В отчёте v4 `product`, `buyer` и `value_mechanism` имеют структуру `{facts: [{text, url}], opinion}`: отдельные факты со ссылками и мнение агента. Массив `facts` может быть пустым. Самостоятельный `score.py` принимает как такие объекты для `product`/`buyer`, так и строки из прежних входов калькулятора; готовый дайджест следует строгому контракту v4; конкуренты — в `competition`, см. [контракт](report.md#competition-конкуренты).

```bash
python3 /path/to/ai-b2b-radar/scripts/report.py digest.json --output digest.html
python3 /path/to/ai-b2b-radar/scripts/score.py entries.json --output ranked.json
python3 /path/to/ai-b2b-radar/scripts/check.py
```

Калькулятор валидирует структуру и обоснования, считает сумму/диапазон и возвращает `ranked` и `needs_data` с версией шкалы `sellability-v2`. Полные оценки сортируются по сумме, уверенности и ID; неполные — по ID. `report.py` разделяет эти результаты по категориям. При неизвестных боли, покупателе или экономической ценности уверенность приводится к `low` с пояснением. `score=null` обозначает неполную оценку; пять неизвестных в отчёте показываются как «недостаточно данных».

Содержательную истинность ссылок и качество обоснований проверяет агент. Проверка скрипта обеспечивает воспроизводимость расчёта для одинакового входного JSON. Некорректный ввод даёт exit code 2, файл результата при этом не создаётся.

## Генерация HTML

`report.py` использует поставляемый вместе со скиллом `scripts/report.html`. Из валидного JSON он напрямую создаёт один HTML-файл со стилями, поиском, фильтрами категорий и подробностями карточки в боковом диалоге. Главные функции берутся из `features`, краткое описание продукта — из `description`. Для покупателей, предложения и экономического механизма шаблон отдельно показывает факты с источниками и мнение агента. Расчёты, структура и разметка выполняются скриптом; модель нужна для исследования и заполнения данных.

Храни рядом исходный `.json` и созданный `.html`. Для переноса скопируй всю папку скилла, включая шаблон. HTML открывается в браузере офлайн. Если харнесс не исполняет Python, сохрани JSON v4 для запуска той же команды в подходящей среде.
