# Контракт дайджеста v4

`report.py` принимает JSON, проверяет типы и обязательные поля, рассчитывает оценки через `score.py` и напрямую создаёт самостоятельный HTML по шаблону `scripts/report.html`. Поля объектов перечислены исчерпывающе: неизвестные поля считаются ошибкой. Рабочий пример: [examples/jev.json](../examples/jev.json). Это пример одной карточки, а полный выпуск собирается из исследованных находок всех трёх категорий.

## Корневой объект

| Поле | Тип | Содержание |
|---|---|---|
| `schema_version` | string, `ai-b2b-digest/v4` | Версия формата |
| `meta` | object | Рамка выпуска |
| `entries` | array of entry | Уникальные продукты, инструменты и модельные семейства |
| `coverage` | непустой array of source | Покрытие лент и тематического поиска |

## meta

Все значения — непустые строки: `period_start`, `period_end` (YYYY-MM-DD, UTC, обе даты включительно), `generated_at` (ISO timestamp с часовым поясом), `market`, `segment`, `summary` (краткий вывод о возможностях текущего выпуска).

## entry

| Поле | Тип | Содержание |
|---|---|---|
| `id` | string | Уникальный ID карточки |
| `category` | enum | `products`, `tools`, `models` |
| `family` | string | Стабильное имя семейства; у моделей одна карточка на семейство |
| `technology` | string | Название найденного продукта, инструмента или модели |
| `url` | HTTP(S) URL | Официальная страница или первичный репозиторий |
| `event_date` | YYYY-MM-DD or null | Дата события в периоде; null при отсутствии подтверждения |
| `description` | string | Коротко о продукте: что это и какую работу выполняет |
| `features` | array of 1–5 strings | Главные функции из прочитанных материалов |
| `product` | analysis | Что продавать: предложение и результат для клиента |
| `buyer` | analysis | Покупатели: сегмент, пользователь и владелец бюджета |
| `value_mechanism` | analysis | Экономический механизм: затраты/выручка клиента, условия и допущения |
| `applications` | array of 1–3 strings | Конкретные применения внутри одной карточки |
| `competition` | object | Конкуренты и сводка агента, см. ниже |
| `criteria` | object | Пять оценок по [шкале](scoring.md) |
| `confidence` | enum | `low`, `medium`, `high` — уверенность в потенциале |
| `confidence_reason` | string | Основания уровня уверенности |
| `validation` | string | Гипотеза о спросе или ценности и способ её проверить |

Все строки непустые. Описание и функции объясняют сам продукт, дата события хранится отдельно.

## analysis: факты и мнение агента

Объекты `product`, `buyer` и `value_mechanism` имеют ровно два поля:

| Поле | Тип | Содержание |
|---|---|---|
| `facts` | array of fact | Сведения, найденные в прочитанных источниках; допустим пустой массив |
| `opinion` | string | Непустая интерпретация или продуктовая гипотеза агента |

Каждый `fact` имеет ровно `text` (непустая строка) и `url` (прямая HTTP(S)-ссылка на источник утверждения). Для заявления разработчика сохраняй атрибуцию в тексте: «Разработчик описывает…», «В кейсе поставщика заявлено…». Само наличие такого заявления подтверждено источником; результат его независимой проверки устанавливается отдельно.

Если сведения о покупателях, предложении или экономике в источниках не найдены, оставь соответствующий `facts` пустым. Рендерер покажет отсутствие найденных фактов. Собственные выводы, предполагаемые сегменты, расчёты экономии и условия применимости помещай в `opinion`. Каждый из трёх пунктов аналитики отображается с отдельными подписями «Факты из источников» и «Мнение агента».

```json
{
  "facts": [],
  "opinion": "Потенциальный покупатель — руководитель поддержки с большим потоком однотипных обращений; готовность платить стоит проверить интервью о текущих затратах."
}
```

## Оценки

В `criteria` ровно пять ключей: `pain`, `buyer`, `value`, `repeatability`, `timing`. Каждый содержит:

- `value`: целое 0, 5, 10, 15, 20 либо null.
- `kind`: `fact`, `vendor_claim`, `hypothesis`, `unknown`; null соответствует `unknown`.
- `reason`: непустое обоснование оценки.
- `evidence`: массив строк со ссылками на прочитанные источники/предоставленные файлы. Для `fact` и `vendor_claim` требуется минимум одна ссылка.

## competition: конкуренты

Ровно `summary` (непустое мнение агента: чем задачу закрывают сейчас, насыщенность, место для входа; для рынка РФ — выполненный поиск российского аналога) и `alternatives` (массив, пустой — проверенный конкурент не найден).

| Поле альтернативы | Тип | Содержание |
|---|---|---|
| `name` | string | Название продукта или описание текущего процесса |
| `url` | HTTP(S) URL or null | Страница конкурента; `null` только для `manual` |
| `type` | enum | `manual` (ручной процесс), `builtin` (встроенная функция платформы), `commercial` (платный продукт), `open_source` |
| `market` | enum | `ru`, `global` |
| `price` | fact or null | Цена со ссылкой на страницу тарифов; `null` — цена не найдена |
| `facts` | array of fact | Сведения о конкуренте со ссылками; допустим пустой массив |
| `covers` | string | Какую часть задачи покупателя закрывает |
| `edge` | string | Чем идея карточки выигрывает |
| `gap` | string | Где конкурент сильнее или что мешает переключению |

`fact` — тот же объект `{text, url}`, что в аналитике. Контракт связывает конкурентов с оценкой (нарушение — ошибка, exit 2):

- `timing.value` ≥ 15 требует минимум двух альтернатив, из них хотя бы одной не `manual`;
- `timing.kind = fact` требует альтернативы с непустыми `facts` или `price`;
- `confidence` `medium`/`high` требует непустого `alternatives`.

Отдельные версии, квантизации и дообучения одной модельной семьи объединяются; разные бизнес-применения перечисляются в `applications`.

## source в coverage

Ровно `source` (уникальное непустое имя), `status` (`checked`, `partial`, `unavailable`, `stale`, `not_checked`), `checked` и `selected` (целые ≥ 0, selected ≤ checked), `note` (непустое примечание: запрос, свежесть, ограничение выдачи, глубина просмотра).

`selected` — число уникальных сущностей выпуска, найденных через этот источник; одна сущность может иметь несколько источников. Общее число карточек считается из `entries`, а не из суммы столбца `selected`.

## HTML

Постоянная структура выпуска:

1. Краткий вывод.
2. Продукты и бизнес-сервисы.
3. Инструменты и инфраструктура.
4. Модели и методы ML.
5. Конкурентный ландшафт.
6. Покрытие источников.

Внутри категории сначала идут полные оценки, затем карточки «На проверку» с диапазоном. Весь выпуск — один файл с локальными стилями и поведением: кремовый фон, зелёные акценты, компактные карточки, поиск и фильтры категорий.

Нажатие на карточку открывает боковой диалог с кратким описанием продукта, главными функциями, покупателями, предложением, экономическим механизмом, применениями, таблицей конкурентов (тип, рынок, цена, что закрывает, преимущество идеи, где конкурент сильнее), оценками с обоснованиями, уверенностью и проверкой спроса. Факты каждого пункта аналитики имеют собственные ссылки; мнение агента отображается отдельно. Диалог доступен с клавиатуры и закрывается Escape. На карточке виден счётчик конкурентов. Конкурентный ландшафт вычисляется из данных: по каждой категории число конкурентов по типам, карточки с российским аналогом, карточки без проверенного конкурента и конкуренты, встречающиеся в нескольких карточках.

Агент заполняет типизированные данные, а генератор воспроизводит структуру по единому шаблону. Для одинакового JSON результат и оценки одинаковы. HTML работает офлайн; переход к источникам требует сети.

```bash
python3 /path/to/ai-b2b-radar/scripts/report.py digest.json --output digest.html
```

При ошибке контракта скрипт завершится с кодом 2 до создания отчёта. Существующий файл сохраняется; выбери новое имя. Для просмотра HTML в stdout опусти `--output`. Если исполнение недоступно, сохрани JSON v4 для генерации HTML в среде с Python.
