# Бесплатные источники

Это небольшой постоянный набор каналов обнаружения. Официальные сайты найденных продуктов исследуются по ссылкам, без ручного добавления в реестр. Адреса — точки входа; доступность и свежесть проверяются при каждом запуске.

## GitHub

- [Trending за неделю](https://github.com/trending?since=weekly) — сигнал интереса, не список новых релизов и не API.
- [Поиск репозиториев](https://github.com/search?type=repositories) — тематический поиск через публичную страницу или REST `GET https://api.github.com/search/repositories` с параметром `q`.
- Примеры запросов: `topic:llm created:>=YYYY-MM-DD archived:false`, `topic:ai-agents pushed:>=YYYY-MM-DD archived:false`. Подставляй начало периода; добавляй термины нужной задачи, например OCR, speech, documents. Не ограничивайся только этими topics.
- Сборщик распределяет выборку между агентами, автоматизацией процессов, документами и ML. Для отдельной задачи используй `--query`, например `invoice automation in:readme pushed:>=YYYY-MM-DD`.
- У перспективного репозитория проверь README, ссылку homepage и Releases. Старые проекты с новым значимым релизом тоже подходят.
- [Синтаксис поиска](https://docs.github.com/en/search-github/searching-on-github/searching-for-repositories), [REST Search](https://docs.github.com/en/rest/search/search#search-repositories).

Работай в доступных бесплатных лимитах; существующая разрешённая авторизация необязательна. При ограничении API используй публичный интерфейс или отметь пробел, не создавай новые аккаунты. Прирост звёзд считай только при наличии двух измерений с датами; текущее количество не является приростом.

## Хабр

- [RSS: машинное обучение](https://habr.com/ru/rss/hubs/machine_learning/articles/?fl=ru).
- [RSS: искусственный интеллект](https://habr.com/ru/rss/hubs/artificial_intelligence/articles/?fl=ru).
- Если RSS недоступен: [ML](https://habr.com/ru/hubs/machine_learning/articles/), [AI](https://habr.com/ru/hubs/artificial_intelligence/articles/).

Ищи релизы, внедрения и конкретные рабочие процессы. Из статьи переходи к первоисточнику продукта; для коммерческой оценки полезны детали процесса и обсуждение пользователей. Дедуплицируй статьи между хабами. Эти ленты охватывают статьи, а не все новости Хабра; старые записи могут выпадать из ограниченной ленты.

## Hugging Face

- [Модели](https://huggingface.co/models), [Spaces](https://huggingface.co/spaces), [Papers](https://huggingface.co/papers).
- Публичные списки: `https://huggingface.co/api/models?sort=lastModified&direction=-1&limit=30` и `https://huggingface.co/api/spaces?sort=lastModified&direction=-1&limit=30`.
- [Документация Hub API](https://huggingface.co/docs/hub/api).

Просматривай карточки по задаче и подтверждай, что именно изменилось. `lastModified` — дата изменения карточки/репозитория, не обязательно релиза. Группируй производные веса и версии по базовому семейству; отбирай разнообразные классы задач: классификация, извлечение, речь, изображения, табличные данные, генерация. Для разделов продуктов и инструментов основной поиск веди по рабочим процессам бизнеса и готовым решениям. У статьи без готового продукта сформулируй новую возможность и явно укажи исследовательскую зрелость.

## Hacker News

- [Show HN](https://news.ycombinator.com/show), [Launch HN](https://news.ycombinator.com/launches).
- Официальный API: `https://hacker-news.firebaseio.com/v0/showstories.json` и `https://hacker-news.firebaseio.com/v0/newstories.json` возвращают ID.
- Элемент: `https://hacker-news.firebaseio.com/v0/item/ID.json`; обсуждение: `https://news.ycombinator.com/item?id=ID`.
- [Описание API](https://github.com/HackerNews/API).

Выбирай продуктовые запуски, затем читай релевантные комментарии о задаче, цене и альтернативах. В API пропускай `null`, `deleted`, `dead` и элементы не типа `story` при поиске запусков. Поле `time` — Unix timestamp в секундах; отсутствие `url` допускается. Не выгружай всё дерево комментариев. Текущие списки не гарантируют покрытие всей недели.

## Y Combinator

- [Каталог компаний](https://www.ycombinator.com/companies).
- [Запуски YC](https://www.ycombinator.com/launches).

Открывай публичные карточки по AI и задачам B2B. Получай описание покупателя и ссылку на компанию. Не считай год батча датой запуска технологии. Сборщик читает ссылки из HTML страницы запусков, а если она отдаёт JSON с `hits`, извлекает записи из него. Если каталог требует JS, используй доступный браузер или веб-поиск по `site:ycombinator.com/companies` с терминами задачи.

## AINews / smol.ai

- [Открытый архив](https://news.smol.ai/).
- [RSS](https://news.smol.ai/rss.xml).

Используй как канал обнаружения обсуждений из X, Reddit и Discord; проверяй проекты по исходным ссылкам. Если RSS даёт лишь краткую аннотацию, открой выпуск в архиве. Проверяй максимальную дату всех полученных записей, не только первой; старый выпуск не становится свежим от сегодняшнего HTTP 200.

## Поиск конкурентов

Ищи по задаче покупателя, а не по названию найденной технологии: «<задача> <сегмент> сервис/software», «<задача> автоматизация», «alternatives to <продукт>». Открытые каталоги: страницы категорий Product Hunt, G2, Capterra; для РФ — vc.ru, Хабр, каталоги отечественного ПО и сайты интеграторов. Встроенные функции проверяй в документации платформ, которыми сегмент уже пользуется (CRM, helpdesk, ERP, офисные пакеты). Цену бери со страницы тарифов конкурента; «по запросу» — тоже факт со ссылкой. Сниппет поиска — повод открыть страницу, а не подтверждение.

## Проверка спроса

Открытые страницы найденного разработчика, цены альтернатив, кейсы клиентов и содержательные публичные обсуждения. Ищи по названию задачи и сегмента, а не только по названию новой технологии. Недоступный кейс отмечай как непроверенный.

Для нового канала сначала проверь открытый способ чтения и условия доступа. При недоступности источника фиксируй пробел и продолжай по доступным каналам.
